## Resumen Ejecutivo

Se implementó la funcionalidad de interfaces duales que permite a los usuarios elegir entre `IRequestHandler` (Task) e `ISyncRequestHandler` (ValueTask) según su caso de uso.

| Interfaz | Return Type | Caso de Uso |
|----------|-------------|-------------|
| `IRequestHandler<,>` | `Task<T>` | General (default) |
| `ISyncRequestHandler<,>` | `ValueTask<T>` | Cache hits, validaciones, operaciones sync |
| `ISyncNotificationHandler<>` | `ValueTask` | Notificaciones que completan sync |

## 🔄 PENDIENTE: Análisis de Rendimiento

### Objetivo
Verificar que `ISyncRequestHandler` con `ValueTask` realmente ofrece beneficios de rendimiento comparado con `IRequestHandler` con `Task`.

### Benchmarks a Crear

```csharp
// test/MediateX.Benchmarks/SyncHandlerBenchmarks.cs

[MemoryDiagnoser]
public class SyncHandlerBenchmarks
{
    // 1. Handler que retorna valor cacheado (sync completion)
    [Benchmark(Baseline = true)]
    public Task<Config> TaskHandler_CachedValue();

    [Benchmark]
    public ValueTask<Config> ValueTaskHandler_CachedValue();

    // 2. Handler que hace I/O async
    [Benchmark]
    public Task<User> TaskHandler_AsyncIO();

    [Benchmark]
    public ValueTask<User> ValueTaskHandler_AsyncIO();

    // 3. Comparación con/sin pipeline behaviors
    [Benchmark]
    public Task<Config> TaskHandler_WithBehaviors();

    [Benchmark]
    public ValueTask<Config> ValueTaskHandler_WithBehaviors();
}
```

### Métricas a Medir

| Métrica | Descripción |
|---------|-------------|
| Mean (ns) | Tiempo promedio de ejecución |
| Allocated (B) | Bytes asignados por operación |
| Gen0/Gen1/Gen2 | Colecciones de GC |

### Hipótesis a Validar

1. **Sync completion:** `ISyncRequestHandler` debe tener ~0 allocations cuando retorna un valor ya disponible
2. **Async completion:** Ambos handlers deben tener rendimiento similar cuando hacen I/O real
3. **Con behaviors:** El overhead de los behaviors debe ser similar para ambos tipos

## Diseño Implementado

### Flujo de Resolución

```
mediator.Send(request)
         │
         ▼
┌─────────────────────────────────────────────────┐
│ SyncRequestHandlerWrapper.Handle()              │
│                                                 │
│ 1. Try resolve ISyncRequestHandler<,> first     │
│ 2. If found → Use ValueTask path                │
│ 3. If not → Fall back to IRequestHandler<,>    │
│ 4. Apply pipeline behaviors                     │
│ 5. Return Task<TResponse>                       │
└─────────────────────────────────────────────────┘
```

### Prioridad de Handlers

```
ISyncRequestHandler > IRequestHandler
```

Si el usuario registra ambos, se usa `ISyncRequestHandler`.

## Ejemplo de Uso

```csharp
// OPCIÓN 1: Task (default) - Sin restricciones
public class GetUserHandler : IRequestHandler<GetUser, User>
{
    public async Task<User> Handle(GetUser request, CancellationToken ct)
    {
        return await _db.Users.FindAsync(request.Id, ct);
    }
}

// OPCIÓN 2: ValueTask (opt-in) - Máximo rendimiento
public class GetCachedConfigHandler : ISyncRequestHandler<GetConfig, Config>
{
    public ValueTask<Config> Handle(GetConfig request, CancellationToken ct)
    {
        if (_cache.TryGet(request.Key, out var config))
            return new ValueTask<Config>(config);  // Zero allocation

        return new ValueTask<Config>(LoadFromDbAsync(request.Key, ct));
    }
}
```
