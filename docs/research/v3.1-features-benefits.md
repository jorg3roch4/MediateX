## 1. Result - Manejo Funcional de Errores

**Estado:** Implementado

**Archivos:**
- `src/MediateX/Contracts/Result.cs`
- `src/MediateX/Contracts/IResultRequest.cs`

### Problema que Resuelve

Las excepciones como mecanismo de control de flujo tienen varios problemas:

```csharp
// Antes: Excepciones como control de flujo (costoso, impredecible)
public async Task<User> Handle(CreateUserCommand cmd, CancellationToken ct)
{
    if (await _repo.EmailExists(cmd.Email))
        throw new DuplicateEmailException();

    return await _repo.Create(cmd);
}

// Uso: try/catch en todos lados
try {
    var user = await mediator.Send(command);
} catch (DuplicateEmailException) { ... }
```

### Solucion

```csharp
// Despues: Errores explicitos en el tipo de retorno
public async Task<Result<User>> Handle(CreateUserCommand cmd, CancellationToken ct)
{
    if (await _repo.EmailExists(cmd.Email))
        return Result<User>.Failure("DuplicateEmail", "Email already exists");

    return Result<User>.Success(await _repo.Create(cmd));
}

// Uso: Pattern matching, sin try/catch
var result = await mediator.Send(command);
return result.Match(
    onSuccess: user => Ok(user),
    onFailure: error => BadRequest(error.Message)
);
```

### Beneficios

| Aspecto | Excepciones | Result |
|---------|-------------|--------|
| Performance | ~1000x mas lento en throw | Cero overhead |
| Flujo de codigo | Invisible, salta stack frames | Explicito, lineal |
| Composicion | Dificil encadenar | `.Map()`, `.Bind()` funcionales |
| Documentacion | Oculto en implementacion | Visible en firma del metodo |

### API

```csharp
// Creacion
Result<T>.Success(value)
Result<T>.Failure(error)
Result<T>.Failure(code, message)

// Consulta
result.IsSuccess / result.IsFailure
result.Value     // throws si es failure
result.Error     // throws si es success

// Transformacion funcional
result.Match(onSuccess, onFailure)
result.Map(value => newValue)
result.Bind(value => Result<NewT>)

// Tipo void
Result.Success()
Result.Failure(error)
```

## 2. ValidationBehavior - Validacion en Pipeline

**Estado:** Implementado

**Archivos:**
- `src/MediateX/Validation/IRequestValidator.cs`
- `src/MediateX/Validation/ValidationResult.cs`
- `src/MediateX/Validation/ValidationException.cs`
- `src/MediateX/Behaviors/ValidationBehavior.cs`

### Problema que Resuelve

Validacion duplicada y mezclada con logica de negocio:

```csharp
// Antes: Validacion mezclada en cada handler
public class CreateUserHandler : IRequestHandler<CreateUserCommand, User>
{
    public async Task<User> Handle(CreateUserCommand cmd, CancellationToken ct)
    {
        if (string.IsNullOrEmpty(cmd.Name))
            throw new ValidationException("Name required");
        if (string.IsNullOrEmpty(cmd.Email))
            throw new ValidationException("Email required");

        return await _repo.Create(cmd);
    }
}
```

### Solucion

```csharp
// Validador separado
public class CreateUserValidator : IRequestValidator<CreateUserCommand>
{
    public ValueTask<ValidationResult> ValidateAsync(CreateUserCommand cmd, CancellationToken ct)
    {
        return ValueTask.FromResult(
            new ValidationResultBuilder()
                .RequireNotEmpty(cmd.Name, "Name")
                .RequireNotEmpty(cmd.Email, "Email")
                .Build());
    }
}

// Handler limpio
public class CreateUserHandler : IRequestHandler<CreateUserCommand, User>
{
    public async Task<User> Handle(CreateUserCommand cmd, CancellationToken ct)
    {
        return await _repo.Create(cmd);
    }
}
```

### Beneficios

| Beneficio | Descripcion |
|-----------|-------------|
| Separacion de responsabilidades | Handlers limpios, validadores reutilizables |
| Ejecucion automatica | Pipeline ejecuta validadores antes del handler |
| Multiples validadores | Puedes tener N validadores por request |
| Errores agregados | Retorna todos los errores, no solo el primero |
| Testeable | Validadores se testean aislados del handler |

### Configuracion

```csharp
services.AddMediateX(cfg =>
{
    cfg.RegisterServicesFromAssemblyContaining<MyHandler>();
    cfg.AddValidationBehavior();
    cfg.AddRequestValidator<CreateUserValidator>();
});
```

## 3. LoggingBehavior - Logging Automatico de Requests

**Estado:** Implementado

**Archivos:** `src/MediateX/Behaviors/LoggingBehavior.cs`

### Problema que Resuelve

Logging manual repetitivo en cada handler:

```csharp
// Antes: Logging duplicado (~15-20 lineas por handler)
public class CreateUserHandler : IRequestHandler<CreateUserCommand, User>
{
    private readonly ILogger<CreateUserHandler> _logger;

    public async Task<User> Handle(CreateUserCommand cmd, CancellationToken ct)
    {
        _logger.LogInformation("Handling CreateUserCommand");
        var stopwatch = Stopwatch.StartNew();

        try
        {
            var user = await _repo.Create(cmd);
            _logger.LogInformation("Completed in {Ms}ms", stopwatch.ElapsedMilliseconds);
            return user;
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed after {Ms}ms", stopwatch.ElapsedMilliseconds);
            throw;
        }
    }
}
```

### Solucion

```csharp
// Configuracion
services.AddMediateX(cfg =>
{
    cfg.RegisterServicesFromAssemblyContaining<CreateUserHandler>();
    cfg.AddLoggingBehavior();
});

// Handler limpio
public class CreateUserHandler : IRequestHandler<CreateUserCommand, User>
{
    public async Task<User> Handle(CreateUserCommand cmd, CancellationToken ct)
        => await _repo.Create(cmd);
}

// Logs automaticos:
// [INF] Handling CreateUserCommand
// [INF] Handled CreateUserCommand in 45ms
// [WRN] Handled CreateUserCommand in 650ms (exceeded threshold)
// [ERR] Request CreateUserCommand failed after 12ms
```

### Beneficios

| Beneficio | Impacto |
|-----------|---------|
| Menos codigo | -750 a -1000 lineas en app tipica |
| Consistencia | 100% requests con mismo formato |
| Observabilidad | Deteccion automatica de problemas |
| Performance | Zero allocations en hot path |
| Mantenibilidad | Un lugar para cambiar logging |

### Configuracion

```csharp
cfg.AddLoggingBehavior(options =>
{
    options.LogRequestStart = true;
    options.LogRequestFinish = true;
    options.LogRequestException = true;
    options.SlowRequestThresholdMs = 1000;
});
```

## 4. RetryBehavior - Reintentos Automaticos con Backoff

**Estado:** Implementado

**Archivos:** `src/MediateX/Behaviors/RetryBehavior.cs`

### Problema que Resuelve

Manejo manual de reintentos en cada handler:

```csharp
// Antes: Logica de retry duplicada
public class CallApiHandler : IRequestHandler<CallApiCommand, ApiResponse>
{
    public async Task<ApiResponse> Handle(CallApiCommand cmd, CancellationToken ct)
    {
        var maxRetries = 3;
        for (int attempt = 1; attempt <= maxRetries; attempt++)
        {
            try
            {
                return await _httpClient.GetAsync(cmd.Url, ct);
            }
            catch (HttpRequestException) when (attempt < maxRetries)
            {
                await Task.Delay(200 * attempt, ct);
            }
        }
        throw new Exception("Max retries exceeded");
    }
}
```

### Solucion

```csharp
// Configuracion
services.AddMediateX(cfg =>
{
    cfg.RegisterServicesFromAssemblyContaining<CallApiHandler>();
    cfg.AddRetryBehavior(opt =>
    {
        opt.MaxRetryAttempts = 3;
        opt.UseExponentialBackoff = true;
    });
});

// Handler limpio
public class CallApiHandler : IRequestHandler<CallApiCommand, ApiResponse>
{
    public async Task<ApiResponse> Handle(CallApiCommand cmd, CancellationToken ct)
        => await _httpClient.GetAsync(cmd.Url, ct);
}

// Reintentos automaticos:
// Intento 1: falla -> espera 200ms
// Intento 2: falla -> espera 400ms
// Intento 3: falla -> espera 800ms
// Intento 4: exito!
```

### Beneficios

| Beneficio | Impacto |
|-----------|---------|
| Menos codigo | Elimina 15-25 lineas de retry logic por handler |
| Backoff exponencial | Evita saturar servicios |
| Jitter automatico | Previene thundering herd |
| Filtrado de excepciones | Solo reintenta errores transitorios |
| Integracion con Result | RetryResultBehavior disponible |

### Configuracion

```csharp
cfg.AddRetryBehavior(opt =>
{
    opt.MaxRetryAttempts = 5;
    opt.BaseDelay = TimeSpan.FromMilliseconds(100);
    opt.MaxDelay = TimeSpan.FromSeconds(10);
    opt.UseExponentialBackoff = true;
    opt.UseJitter = true;
    opt.ShouldRetryException = ex => ex is HttpRequestException;
});
```

## 5. TimeoutBehavior - Control de Tiempo de Ejecucion

**Estado:** Implementado

**Archivos:** `src/MediateX/Behaviors/TimeoutBehavior.cs`

### Problema que Resuelve

Requests que se cuelgan indefinidamente:

```csharp
// Antes: Sin control de timeout
public class CallApiHandler : IRequestHandler<CallApiCommand, ApiResponse>
{
    public async Task<ApiResponse> Handle(CallApiCommand cmd, CancellationToken ct)
    {
        // Si el servicio no responde... espera infinita
        return await _httpClient.GetAsync(cmd.Url, ct);
    }
}
```

### Solucion

```csharp
// Configuracion
services.AddMediateX(cfg =>
{
    cfg.RegisterServicesFromAssemblyContaining<CallApiHandler>();
    cfg.AddTimeoutBehavior(opt =>
    {
        opt.DefaultTimeout = TimeSpan.FromSeconds(30);
    });
});

// Handler sin cambios - timeout automatico
public class CallApiHandler : IRequestHandler<CallApiCommand, ApiResponse>
{
    public async Task<ApiResponse> Handle(CallApiCommand cmd, CancellationToken ct)
        => await _httpClient.GetAsync(cmd.Url, ct);
}

// Si excede el timeout:
// [WRN] Request CallApiCommand timed out after 30000ms
// throw TimeoutException
```

### Beneficios

| Beneficio | Impacto |
|-----------|---------|
| Proteccion contra cuelgues | Requests nunca esperan indefinidamente |
| Timeouts por tipo | Diferentes timeouts segun el request |
| Interface IHasTimeout | Requests definen su propio timeout |
| Integracion con Result | TimeoutResultBehavior disponible |

### Configuracion

```csharp
cfg.AddTimeoutBehavior(opt =>
{
    opt.DefaultTimeout = TimeSpan.FromSeconds(60);
    opt.SetTimeout<FastQuery>(TimeSpan.FromSeconds(5));
    opt.SetTimeout<SlowReportQuery>(TimeSpan.FromMinutes(5));
});
```
